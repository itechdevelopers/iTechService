Акция «Каждое 5-е стекло» — /one_c_functions/glass

Доступ: любой вошедший сотрудник. Анонимные запросы проходят обычную проверку Devise.
Существующие ограничения поиска по артикулу сохранены отдельным article? на сервере.
Телефон отправляется POST с CSRF, скрыт фильтром логов, не попадает в URL или аргументы фоновой задачи.
Ключ поиска в сессии привязан к нормализованному телефону через HMAC. Истории разных карт не смешиваются.

Инфраструктура: существующие Sidekiq/Redis, AIS_ONE_C_PYTHON и AIS_ONE_C_ODATA_CONNECTOR.
Новые секреты, роли, таблицы, миграции и настройки самой 1С не требуются.
Python использует существующий odata.py; разрешены только GET. Единственное исключение из требований
коллекций $select/$filter/$top — чтение конкретной singleton-константы цены акции (одна запись).
Общий кеш 90 секунд, предыдущий успешный результат хранится сутки и явно помечается устаревшим.
Поиск запускается по кнопке, без фонового опроса базы. Опрос страницы читает только Redis.
Одна задача чтения 1С одновременно, процесс до 120 секунд, лимит 100 GET; 10 поисков/мин на сотрудника.
Полная история карты до 1000 движений и 500 чеков каждого вида. Достижение лимита с продолжением
не выдаётся за полный результат. Дубли ключей движений запрещены. Ошибка сохраняет предыдущий кеш.

Источники:
- Document_УстановкаЛояльностиПоТовару a3a42325-d13c-11e9-80db-968d2a071e7d: КоличествоДляАкции=5.
- Товары этого документа + номенклатура исторических движений карты.
- Constant_ЦенаТовараПоЛояльности: фактическая цена акции (на проверке 1 рубль).
- AccumulationRegister_ПродажиПоКартеЛояльности_RecordType и Balance: карта, правило, товар, количество,
  RecordType, Recorder, Period. Receipt увеличивает, Expense уменьшает счётчик.
- ЧекККМ и ЧекККМВозврат с Posted=true, Статус=Пробит, DeletionMark=false; архивные чеки включены.
- Продавец строки / Кассир чека и Склад_Key: сотрудники и филиалы.

Методика:
Списания пяти накоплений показаны отдельно от продаж по цене акции. На проверенной карте списание
появляется на следующей платной покупке; встречается также при начале учёта. Это не доказательство
получения подарка и тем более не доказательство отказа в подарке.
Строка «по цене акции» определяется по фактической Сумма/Количество, а не gmb_Подарок (на проверенных
пятых стёклах этот флаг false). Это ценовой признак, не утверждение о физической поклейке.
Цена проверяется по текущей настройке; если историческая настройка менялась, сверка не подтверждает
готовность подарка автоматически. Все суммы сопоставляются через Decimal.
Для подтверждённого прогресса требуются: полная выборка, совпадение суммы движений с Balance,
совпадение количества чеков с приходами регистра, корректное число акционных единиц в каждом чеке.
Новые чеки открытой смены допускаются как явно подписанное дополнение, только когда точно объясняют
разницу с регистром. Архивные чеки и движения никогда не складываются как дополнительные продажи.
Прогресс — остаток количества по модулю 5, проверенный по истории чеков. Отрицательный исходный баланс
показывается как есть (например -4 соответствует первому стеклу нового цикла), не считается долгом.
Возвраты видны и уменьшают общее количество, но автоматически подтверждать дальнейший подарок при
возвратах нельзя без проверки правил восстановления цикла: UI явно просит проверку в 1С.
При расхождениях, дробных количествах, неполноте, неактивной карте или устаревшем кеше обещание подарка
не показывается. Финальную цену применяет касса 1С. Дата и сотрудник — по чеку, не акт выполнения поклейки.
