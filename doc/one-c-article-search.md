# Поиск по артикулу в 1С

В АИС: **Торговля → Функция 1С → Поиск по артикулу**. Окно принимает
артикул или код 1С как строку, включая ведущие нули. Поиск точный:
`Catalog_Номенклатура.Артикул` либо `Code`, без удалённых элементов и папок.
Все совпадения показаны без произвольного выбора первого товара. Результаты
сгруппированы сначала по магазину/складу 1С, затем внутри него перечислены
товары с характеристиками и штрихкодами. Склады упорядочены по названию.

Остатки читаются непосредственно из
`AccumulationRegister_ТоварыНаСкладах/Balance` на момент запроса, по измерениям
`Номенклатура,Характеристика,Склад`. Показаны группы с `ВНаличииBalance > 0`
и отдельно `КОтгрузкеBalance`. В наличии не означает свободный остаток после
всех резервов. Единица берётся из `Номенклатура.ЕдиницаИзмерения_Key`.

Филиал представлен названием склада из `Catalog_Склады`. Никакого неявного
сопоставления с подразделениями АИС или фильтра по подразделению сотрудника
нет: это право разрешает просмотр всех складов 1С.

Штрихкоды читаются из `InformationRegister_ШтрихкодыНоменклатуры`, только для
найденной номенклатуры, и относятся к её характеристике и упаковке. Они не
являются складским идентификатором конкретного экземпляра, поэтому один
штрихкод может повторяться на нескольких складах. Упаковка подписывается
отдельно; количество в таблице остаётся в базовой единице товара, не в
упаковках. Отсутствие штрихкода/остатка показано явно. Ошибка 1С или неполный
ответ не выдаются за отсутствие товара или нулевой остаток.

## Доступ

Суперадмины имеют доступ автоматически. Остальным требуется новое право
**«Возможность работать с артикулами через 1С»** (`work_with_one_c_articles`)
в профиле сотрудника. Его создаёт data migration
`20261007160000_seed_work_with_one_c_articles`; выдавать его может суперадмин.
Авторизация проверяется также на прямом URL `/one_c_functions` и до запуска
коннектора. Отзыв права действует со следующего запроса. Служебная учётка 1С
не предоставляет сотруднику дополнительных прав АИС.

## Конфигурация и выпуск

Нужны Python 3.9+ с поддержкой `zoneinfo` и уже проверенный защищённый
коннектор `1c-odata-agent` на сервере АИС:

```dotenv
AIS_ONE_C_PYTHON=/usr/bin/python3
AIS_ONE_C_ODATA_CONNECTOR=/opt/1c-odata-agent
```

Пути являются примером и задаются для конкретного сервера. В каталоге
коннектора должны существовать `odata.py`, `local/metadata.xml` и его
защищённая конфигурация подключения. Пользователь процесса АИС должен иметь
право чтения. Пароли не копируются в репозиторий АИС. Код использует текущий
коннектор, настройки OData и синхронизацию не изменяет. Без его установки и
этих переменных поиск выдаёт безопасную ошибку, остальные страницы работают.

Только GET: ни универсального OData-инструмента, ни операций записи нет.
Запросы точечные, литералы экранируются существующим коннектором. Лимиты:
до 10 товаров, менее 100 штрихкодов и менее 100 групп остатков на товар,
45 секунд на весь поиск и 1 МБ на результат. При превышении показана ошибка,
а не частичный список. Точный код товара помогает сузить поиск.

Ветка создана от свежего `origin/master` (`6f275a270`). Выпуск — только после
проверки PR разработчиком, затем merge в текущий master и штатный deploy.
При выпуске выполнить штатные data migrations (`db:migrate:with_data`),
проверить наличие нового права и назначить его нужным сотрудникам. В этой
задаче production, существующий standalone MCP и PR #749 не менялись.

## Ручная проверка

1. Суперадмин открывает раздел; нажать кнопку, ввести артикул и выполнить поиск.
2. Сотрудник без права не видит пункт и не может открыть прямой URL.
3. Суперадмин выдаёт право в профиле: раздел появляется. После отзыва снова
   недоступен, запросов в 1С нет.
4. Проверить ведущие нули, апостроф, несколько совпадений, характеристики,
   упаковки и несколько складов. Штрихкоды других характеристик не выводятся.
5. Проверить отсутствующий товар, товар без остатков и без штрихкодов.
6. При недоступной 1С отображается сообщение об ошибке, не нулевой остаток.

Изолированная локальная проверка использует настоящие Rails, Devise, модели,
Pundit и шаблон. Для сценариев ошибок/неоднозначности ответ внешней 1С
подменяется фикстурами; полный Ruby → Python → OData отдельно проверяется
чтением действующей 1С. Использован временный Selenium compatibility shim
из-за известного `chromedriver-helper` при загрузке Rails на этом Mac.
Это не штатный запуск RSpec; новые тесты в репозиторий не добавлялись.
Визуальную проверку модального окна в браузере выполнить перед выпуском.

Проверено локально: 15 проверок реального Rails и 11 сценариев коннектора;
оба запуска завершились с кодом 0. Контрольный код `00-00013288` вернул
товар со штрихкодом `7770000549979` и остатки на пяти складах. Код
`00-00019052` найден, положительных остатков нет. Сквозной запрос через
авторизованную страницу Rails использовал действующую 1С только на чтение.
Тестовая БД: отдельный PostgreSQL 14, `127.0.0.1:55442/article_test`;
временный кластер после проверки остановлен.

## Брони по магазину

Блок **«Забронировано»** внутри магазина читает положительный
`AccumulationRegister_ТоварыКОтгрузке/Balance.ВРезервеBalance` с группировкой
по складу, товару, характеристике, документу отгрузки и получателю. Это не
`КОтгрузкеBalance` и не просто наличие строки в заказе. Учитываются также
магазины, где есть бронь без положительного остатка; количество в наличии
при этом не подставляется нулём.

Номер брони — `Document_ЗаказКлиента.Number`, связанный через
`ДокументОтгрузки` с подтверждённым типом `Document_ЗаказКлиента`. ФИО берётся
из указанного в заказе контактного лица, иначе показывается полное
наименование партнёра. Телефоны — только из контактной информации этого
лица/партнёра с типом «Телефон». Если используется телефон партнёра, он
подписан как телефон клиента 1С. Отсутствующие ФИО/номер/телефон показаны
явно. Резерв другого вида документа не связывается с произвольным клиентом.
Удалённый/непроведённый заказ при существующем резерве отмечается предупреждением.

Доступ к контактам имеют только те же суперадмины и сотрудники с правом
`work_with_one_c_articles`, прошедшие проверку до обращения к 1С. ФИО и
телефоны не логируются коннектором и не сохраняются в копию каталога.
Исходный защищённый клиент не изменён: лишь в процессе этой функции
разрешён один дополнительный `Balance`, проверенный по метаданным как
`IsSideEffecting=false`. Для его полиморфных ссылок корректируется только
точный порядок сортировки; ограничения пагинации и GET-only остаются прежними.

Повторяющиеся одинаковые связи штрихкод/характеристика/упаковка убираются.
Количество товара показано рядом со штрихкодом и отдельной колонкой —
остаток позиции данного магазина в базовой единице, а не число экземпляров
уникального штрихкода. Разные товары/характеристики/упаковки не складываются
произвольно даже при совпадении штрихкода; разные коды одной позиции не
являются отдельными остатками для суммирования. Количество броней отдельно.
