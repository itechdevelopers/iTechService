# Общая история и оперативные состояния звонков

Источником является рабочая Asterisk 11 / FreePBX, а не браузер АИС. История не зависит от TELEPHONY_ENABLED и охватывает внутренние, входящие и исходящие вызовы обычных телефонов, Softphone и браузеров.

## Уже включено на 2026-10-12

Общий CDR импорт с 2026-10-08: при первой проверке 1093 разговора (275 внутренних, 307 исходящих, 511 входящих), 1092 с путём записи. Новые завершённые вызовы сверяются каждые 15 секунд через Mac LaunchAgent com.itech.telephony-collector. Этот процесс использует существующий API и не требует выкатывать изменения ветки. Одна реальная запись проверена через авторизованный HTTPS Range/SFTP: 206, audio/wav, RIFF. Проверка всех WAV отдельно не заявляется.

Выделенные RSA SSH-ключи находятся в приватной папке Mac вне Git. На АТС authorized_keys сохраняет старые ключи; новые ограничены исходным 192.168.1.109, forced command, без PTY/forwarding/agent/X11. CDR command только SELECT + channel metadata. AMI command подключается локально, делает только Login/Status, выдаёт отфильтрованные события. AMI учётная запись имеет read call/system и write reporting для read-only Status, не имеет originate/call/command/config полномочий управления. Порт AMI не открывался дополнительно. Бэкап: /root/ais-call-history/backup-20261012-135326.

## Изменение для ревью

- Asterisk 11 события Newchannel/Newstate/Dial/Bridge/Hangup и Status snapshot.
- Один логический разговор с участниками; Dial и две половины LocalBridge связывают каналы группы; поздний Status linkedid уточняет группу, временные AMI строки удаляются после объединения. Bridge сам по себе не объединяет независимые разговоры/конференции.
- Состояния «Звонит», «Разговор», «Завершён, сверяется». После CDR — окончательный результат, длительность и запись. Время из uniqueid соответствует началу канала; запись может поступить позже.
- Долговечная SQLite очередь на Mac: объединение новых состояний, подтверждения HTTP, повторная отправка после сбоя, до 100 записей/200KB за запрос. События не пишутся в логи.
- Каждые 30 секунд AMI Status восстанавливает активные каналы. Пропавшие каналы помечаются неопределёнными, не объявляются пропущенными. Окончательный результат берётся из CDR.
- Подписанные heartbeat AMI/CDR. Если события перестали приходить, интерфейс явно показывает недоступность онлайн-связи.
- HTML fragment с той же авторизацией/фильтром/пагинацией 100. Открытая видимая страница опрашивает его каждые 2 секунды; фоновая страница не опрашивается, переход отменяет запрос.
- CDR не откатывается поздним AMI событием; запись сотрудника и номер сохраняются совместно. Savepoint исправляет retry после PostgreSQL unique violation.
- Для истории теперь одинаково разрешены admin/superadmin; аудио сохраняет прежние ограничения.

## Активация после апрува разработчика

1. Интегрировать в актуальный master и выполнить штатный deploy из чистого текущего master согласно AGENTS.md. Миграция добавляет поля/health таблицу, сохраняет историю, отмечает старые CDR как окончательные.
2. Обновить remote ami_stream.py из одобренного релиза. Существующий ingest secret и общий CDR collector оставить. Флаг браузерной телефонии не требуется.
3. Установить live_history.py на рабочий Mac. Заполнить live.example.json приватными путями и существующим ingest secret, state SQLite 0600. В UserKnownHostsFile с пробелами нужны кавычки внутри SSH option; исходный RSA host key должен совпадать с проверенным.
4. Mac сервис KeepAlive запускает Python 3.9+ с --config. Для этого Mac SSL_CERT_FILE=/etc/ssl/cert.pem: публичный CA bundle, без отключения TLS. AMI SSH command root@192.168.1.145, отдельный ais-ami-readonly ключ, HostKeyAlgorithms/PubkeyAcceptedAlgorithms +ssh-rsa, server alive 15/2. Private config, ключи, SQLite не должны попадать в Git.
5. Включить сервис только после migration: старый API не принимает живые статусы. Проверить heartbeat, живой входящий/внутренний/исходящий, группу, обычную трубку и браузер, повтор после сетевого сбоя, итог и запись после завершения. Сопоставить с CDR FreePBX.

Рабочая цель задержки событий — несколько секунд: сборщик отправляет примерно каждые 2 секунды, при постоянном потоке максимум каждые 5; страница опрашивается каждые 2. Это целевая скорость, не заявленный измеренный SLA. CDR сверяется отдельно каждые 15 секунд, импорт старых дат занимает больше времени.

Ограничения: если AMI был недоступен на всём протяжении разговора, CDR восстанавливает итог, но не все этапы/участников. Сложные переводы/конференции могут оставаться отдельными разговорами; нельзя объявлять гарантированную дедупликацию всех исторических CDR, когда в старой БД нет linkedid. Прежде чем включать live режим, измерить эти сценарии на реальной АТС. Ни один отслеживающий процесс не меняет маршрутизацию и не инициирует звонки.

## Справочник и фильтры

В истории добавлена ссылка «Справочник номеров». Используется существующий PhoneLabel, поэтому текущие подписи транскрипций сохраняются. Администратор может создать, изменить или удалить номер/подпись, назначить сотрудника, подразделение АИС и произвольную группу/отдел («Продажи», «Ремонт», «Операторы»). Несколько номеров могут иметь одну группу; новая группа не требует создания подразделения в АИС. Читают справочник сотрудники с доступом к истории, изменяют только admin/superadmin.

Подписи и группы подсвечиваются у звонящего, набранного номера, ответившего и участников. Привязанный через справочник сотрудник учитывается при импорте новых звонков. Исторические номер/сотрудник сохраняются при последующем изменении адресной книги; текущая подпись показана отдельно.

Фильтры: только внешние, направление, результат, даты, группа номеров, подразделение, сотрудник и конкретный номер справочника. Фильтр ищет номер среди источника/назначения/ответившего и AMI участников, включая неответившую трубку группового вызова. Пример: 101 и 102 принадлежат группе «Продажи»; «Только внешние» + «Продажи» показывает обращения этой группы без внутренних разговоров.

«Запомнить фильтры» применяет и сохраняет текущий набор в localStorage, отдельно для ID пользователя в этом браузере. При следующем открытии он восстанавливается. «Забыть фильтры» удаляет сохранённый набор; «Сбросить» временно открывает все звонки без применения набора. На другом браузере/компьютере набор нужно сохранить отдельно. Это один изменяемый набор, не библиотека именованных отчётов.

После расширения: 26 Rails tests / 102 assertions без ошибок; Chrome проверил сохранение/применение/восстановление/удаление набора. Uglifier сборка расширенного JS прошла. Новая миграция только добавляет nullable группу и связи к существующим подписям. В production эти изменения пока не выкатаны.
