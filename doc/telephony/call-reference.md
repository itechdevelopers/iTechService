# ID браузерного звонка

В телефоне под таймером показан компактный ID SIP-диалога; кнопка копирует
полный Call-ID (с fallback для Clipboard API). ID сохраняется после завершения
и заменяется только при следующем звонке. У консультации отдельная кнопка ID.
Это существующий уникальный идентификатор протокола, а не номер клиента или
дополнительная случайная метка. Каждая параллельная браузерная ветка имеет свой
SIP Call-ID; общий разговор на АТС может объединять несколько таких веток.

`newRTCSession.request.call_id` берётся из публичного события JsSIP, включая
входящий/исходящий вызов; нет обращения к приватному `_request`. DOM использует
textContent; строки ограничены 256 ASCII-символами, управляющие символы
отклоняются. Сокращение в интерфейсе — только визуальное, копируется полный ID.

На шлюзе `AIS_CALL_REF` (NOTICE) связывает SIP ID с gateway UNIQUEID/linkedid,
а для входящих — с известным AIS_CALL_ID рабочей АТС. SIP ID в журнале обратимо
URI-кодируется (URIENCODE), поэтому спецсимволы не создают дополнительные строки
журнала и не теряются. Для поиска применяется URI-кодированная версия
скопированного ID. Остальные поля числовые, без номеров клиента, аудио,
SIP-паролей или полного содержимого SIP-пакетов.

Для входящих запись создаётся на PJSIP-канале перед Dial через b-gosub, в том
числе до ответа/отмены. Для исходящих и echo — в существующем разрешённом
маршруте. Если вызов вообще не дошёл до шлюза, строки на сервере может не быть.
Уже завершённые до установки изменения звонки новых ID-строк задним числом не
получают. Один CDR не доказывает причину отсутствия RTP/звука.

## Проверено

30 Rails tests / 216 assertions; Uglifier compile; реальный Chrome и шлюз на
свободном 7779: исходящий и входящий, разные ID, побайтное совпадение с
декодируемым серверным журналом и gateway CDR ID, копирование в clipboard,
сохранение после hangup, звук. Тест `test-call-reference.cjs` добавляет только
временный изолированный маршрут 7799 и Local/incoming, снимает его в finally.
Рабочие контексты и программы шлюза не заменяются в ходе теста.

После developer approval: штатный deploy актуального master; отдельно поставить
одобренный gateway-dialplan.conf с резервной копией и dialplan reload. Asterisk
не перезапускать. Если очередь PR779 будет интегрирована первой, сохранить
b(ais-browser-log-reference^s^1) на Dial внутри ais-browser-queue-member:
диагностировать нужно реальный PJSIP, а не Local половину.
